4. HOW MULTILINGUAL OPTIONS ARE REPRESENTED
-------------------------------------------
Per option object:
  { value: string; label: string; label_hi: string }

  - value    : internal English keyword (language-independent)
  - label    : English display string
  - label_hi : Hindi display string

Per question object:
  { en: string; hi: string }

  - en: English question text
  - hi: Hindi question text

Language switching logic (AyushIntakePage.tsx line 31):
  const getQText = (q) => isHindi ? (q.text.hi || q.text.en) : q.text.en;

Option display (AyushIntakePage.tsx line 78):
  isHindi ? opt.label_hi : opt.label

Only English (label) and Hindi (label_hi) exist for option display.
No Tamil labels (label_ta), no Telugu, no other Indian languages.


5. HOW INTERNAL ANSWER VALUES ARE REPRESENTED
---------------------------------------------
All internal option values are fixed English keywords. They are language-independent:

  slim, medium, heavy
  yes, sometimes, no
  high, regular, low
  constipated, loose
  good, disturbed, insomnia
  dry, oily, normal

These values are the SAME regardless of UI language.
The value is bound to the option object itself, not derived from the label.


6. WHETHER TAMIL / HINDI ANSWERS MAP TO SAME INTERNAL VALUES AS ENGLISH
-----------------------------------------------------------------------
YES — because option values are hardcoded English keywords in the option definition.

Example (cold_sensitivity):
  Hindi option "हाँ, हमेशा"    -> internal value: yes
  English option "Yes, always" -> internal value: yes

Both map to the same internal value: yes.

There is no Tamil option data at all (no label_ta field, no text.ta).
If Tamil were added, it would need label_ta entries with the SAME value keys (yes/no/etc.).
No translation mapping layer exists; value is the authoritative identifier.


7. CURRENT AYURVEDIC MAPPING / SCORING LOGIC
-------------------------------------------
File: frontend-patient/src/pages/AyushIntakePage.tsx

NO scoring logic exists. The page only:

  1. Loads questions from AYUSH_QUESTIONNAIRES[stream]
  2. Shows one question at a time
  3. Stores selected value in answers state (Record<question_id, value>)
  4. Increments question index
  5. On last question: setComplete(true) -> shows completion card
  6. On Continue: navigate(/documents)

No computation of dosha scores, prakriti, agni, koshtha, or any Ayurvedic mapping.

Artifacts that LOOK like scoring infrastructure but are NOT used:

  - scoring_key on each question (e.g. scoring_key: body_build)
    NOT READ anywhere in the codebase.

  - AyushProfile.dominant_dosha: string
    Defined in types (line 110) but never assigned anywhere.

  - AyushProfile.scores: Record<string, number>
    Defined in types (line 111) but never populated anywhere.

  - progress bar in UI = currentIdx / questions.length
    Purely linear UI progress, not Ayurvedic scoring.

  - completion_percentage in AyushProfile type
    Never set by the intake page.
